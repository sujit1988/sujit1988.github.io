9 Career Phases

From cloud engineering to systems leadership — each phase built the next

01

Cloud Engineering & IaC Foundations

2016–2017

Context

Started as a cloud engineer working with AWS, learning CloudFormation, then moving to Terraform. Built the foundational mindset: infrastructure is code, and code is a system you design, not just scripts you write.

Key Work

  • AWS infrastructure provisioning (VPCs, EC2, IAM, S3, RDS)
  • CloudFormation → Terraform migration
  • Terraform module design: reusable, composable, version-controlled
  • Chef cookbooks for configuration management
  • CI/CD pipeline foundations (Jenkins, CodePipeline)

Systems Thinking Seed

Learned that good IaC isn't about individual resources — it's about designing modules that compose into reliable systems. This "think in systems, not scripts" mindset carried forward into every later phase.

Psychology Lens

Even here, human factors mattered: how do you name modules so teams understand them? How do you structure code so newcomers aren't overwhelmed? Cognitive load in codebases is real.

02

DARPA & GovCloud Delivery

2017–2018

Context

Led multi-product delivery into DARPA's AWS GovCloud environments. These were some of the most constrained, high-stakes deployments imaginable: air-gapped networks, STIG compliance, no internet access.

Key Work

  • Designed end-to-end bootstrap runbook for offline deployments
  • Built the "omnibus" artifact bundle for air-gapped environments
  • Managed builder vs target environment architecture
  • Artifactory as "local internet" — all dependencies pre-staged
  • Multi-product coordination: MNC, Radar, Assess, Deploy, Test

Program Leadership Emergence

This was where engineering skill met program coordination. You can't bootstrap an air-gapped platform alone — it requires orchestrating multiple teams, products, and artifact streams into one coherent deployment.

Psychology Lens

Decision-making under extreme constraint. When there's no internet fallback, every dependency must be verified. The cognitive load on operators is immense — which led me to design checklists and manifests that reduced mental burden.

03

STIG Compliance at Scale

2017–2019

Context

STIG (Security Technical Implementation Guides) compliance was required for all DARPA and government deployments. Hundreds of controls per OS, per service. Manual compliance doesn't scale.

Key Work

  • Designed the "STIG Pyramid": Chef (configure) → InSpec (validate) → Nessus (independent scan)
  • Built STIG-hardened AMI pipelines
  • Automated scan-remediate-rescan cycles
  • Partnered with security teams on waivers and exception processes

Compliance-as-Code Philosophy

Security compliance isn't a checkbox — it's a system. The three-layer pyramid ensured that configuration, validation, and independent verification were all automated and repeatable.

Psychology Lens

Compliance fatigue is real. Teams drown in findings if there's no structure. The pyramid model reduced overwhelm by separating "configure," "verify," and "audit" into clear, manageable layers — each with its own feedback loop.

04

SAFe Rollout & Scaled Agile

2018–2019

Context

Rolled out SAFe 4.6 across 7+ products in the platform organization. This wasn't adopting a framework by the book — it was designing an operating model that used SAFe principles but fit real constraints.

Key Work

  • Designed and facilitated PI Planning across US–India distributed teams
  • Established ART (Agile Release Train) cadences
  • Ran Inspect & Adapt sessions and retrospectives
  • Trained Scrum Masters and Product Owners
  • Integrated SAFe with existing Jira structures

Operating Model Design

SAFe gave us a vocabulary and a starting structure. But the real work was tailoring: which ceremonies to keep, which to simplify, how to handle the realities of timezone gaps and mixed maturity teams.

Psychology Lens

Group dynamics in PI Planning are fascinating. Cognitive load peaks during dependency identification. Facilitation techniques — timeboxing, visual boards, structured breakouts — are essentially applied psychology for group decision-making.

05

Story Mapping at Scale

2018–2020

Context

Facilitated 55+ story mapping workshops across products like Deploy, Test, Migrate, MNC, Assess, and Core platform capabilities.

Key Work

  • Developed a repeatable story mapping playbook
  • Converted product visions into user journeys, activities, tasks, and stories
  • Identified "boulders" (large capabilities) that became SAFe epics
  • Created visual story maps that fed directly into PI Planning backlogs
  • Trained POs and architects on facilitating their own sessions

Bridge Between Strategy and Execution

Story mapping was the missing link between "we have a product vision" and "we have a backlog." It made abstract goals concrete and sequenceable.

Psychology Lens

Story mapping is fundamentally a cognitive exercise: externalizing mental models, building shared understanding, reducing ambiguity. My mom's psychology background helped me see these sessions as structured sense-making, not just "planning meetings."

06

Jira + Tempo + CFO Tracking

2018–2020

Context

Designed a data pipeline from Jira issues and Tempo time entries to P&L-level financial reporting for 500+ people. This became the backbone for CFO tracking sheets and shareholder reporting.

Key Work

  • Mapped time entries → issues → epics → products/customers → financial categories
  • Integrated HR cost data (rates per role/band)
  • Built weekly-updated CFO tracking sheets
  • Enabled portfolio decisions: investment mix, profitability, capacity allocation
  • Jira automations for FixVersion propagation, sprint lifecycle, release workflows

Making Engineering Legible to Finance

This was the system that turned "engineering is busy" into "here's exactly where the money goes, by product, customer, and category." Finance and executives could finally see the portfolio.

Psychology Lens

Behavioral economics in action: when people see how their time maps to cost, behavior changes. Some changes are healthy (better prioritization); some need guardrails (avoiding surveillance anxiety). Designing for healthy incentives is applied psychology.

Working under my mom's guidance, I've started to consciously apply psychological frameworks to these interactions.
